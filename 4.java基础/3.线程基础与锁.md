# 线程基础与创建方式
进程Process：每个运行的程序就是一个进程，每个进程有独立内存空间和独立资源
线程Thread：进程中的一个执行路径，每个进程可以有多个线程

## 创建线程
1.继承Thread类，简单任务，不需要继承其他类
```java
public class MyThread extends Thread {
    @Override
    public void run() {
        for (int i = 0; i < 10; i++) {
            System.out.println("线程" + this.getName() + "正在执行第" + i + "次");
        }
    }
}
```
2.实现Runnable接口，最常用，灵活，支持资源共享
```java
public class ThreadDemo2Lambda {
    public static void main(String[] args) {
        // 创建匿名线程，直接传 Lambda表达式
        Thread thread = new Thread(() -> {
            for (int i = 0; i < 10; i++) {
                System.out.println("线程" + thread.getName() + "正在执行第" + i + "次");
            }
        }).start();
    }
}
```
3.使用Callable和Future接口，需要返回结果或抛出异常的任务

⚠️ 注意：启动线程必须用start()方法，不是用run()方法


## 线程的六种状态
1.NEW：新创建，未启动
2.RUNNING：正在运行/就绪
3.BLOCKED：阻塞，等待其他线程释放锁
4.WAITING: 无限期等待另一个线程通知
5.TIMED_WAITING: 等待指定时间
6.TERMINATED: 已终止、执行完毕

## 线程控制方法
```java
thread.start(); // 启动线程
thread.sleep(1000); // 睡眠线程
thread.join(2000); // 阻塞线程2秒，不加时间会无限期等待
thread.yield(); // （一般不使用）主动让出CPU，从运行回到就绪状态，让其他线程执行
thread.interrupt(); // 中断线程
thread.isInterrupted(); // 检查线程是否中断
thread.isAlive(); // 检查线程是否存活
thread.isTerminated(); // 检查线程是否已终止
```

## 守护线程
普通线程：JVM会等待所有用户线程结束才退出: main,自定义线程
守护线程：后台线程，JVM退出时不会等待守护线程结束：垃圾回收线程，监控线程
```java
thread.setDaemon(true); // 设置为守护线程
thread.start(); // 启动线程，守护线程必须在启动前设置
```
注意：
1.setDaemon(true)方法必须在启动线程前调用
2.守护线程不应该执行IO操作或访问资源，因为JVM退出可能会中断
3.守护线程不能持有必须释放的资源，如文件句柄，数据库连接等。
4.适合使用守护线程的场景：监控，日志记录，定时任务，缓存清理等。

# 线程安全问题
2个线程同时操作获取数据，可能会导致数据不一致，要保持原子性

## Synchronized 内置锁
java 内置关键字实现内置锁，保证同一时刻最多只有一个线程执行被 synchronized 保护的代码块，从而保证原子性和可见性。

synchronized特性：
1.互斥性：同一事件只有一个线程能持有锁，其他线程阻塞等待
2.可见性：锁释放时，会将修改刷新到主内存，其他线程可见
3.可重入性：同一个线程可以多次获得同一把锁（不会死锁）

1. 同步实例方法
在方法声明上加上 synchronized，锁住的是当前实例对象（this）
```java
public synchronized void method() {
    // 方法体
    count++;
}
```

2. 同步静态方法
在方法声明上加上 synchronized，锁住的是当前类对象（类名.class）,全局互斥
```java
public static synchronized void method() {
    // 方法体
    count++;
}
```
3. 同步代码块，粒度更细，避免整个锁性能开销
在代码块上加上 synchronized，锁住的是指定的对象
```java
public void method() {
    synchronized (lock) {
        // 方法体
        count++;
    }
}
```

## volatile 关键字
可见性问题：多线程环境下，一个线程对共享变量的修改，其他线程不能及时看到（cpu缓存问题），这就是可见性问题。
volatile 变量：保证变量可比性（立即刷新到主内存），不能保证原子性，适合简单的状态编辑，单例。
1.无锁
2.低开销
3.保证可见性
4.不保证原子性

## Lock接口与ReentrantLock
synchronized局限性：不能中断等待锁的线程，不能尝试获取锁
lock接口：提供灵活的锁机制，定义了锁基本操作，核心实现类ReentrantLock，可重入锁

**java1.6后，synchronized性能已经大幅度优化，优先使用synchronized，除非需要ReentrantLock的额外功能**
## 公平锁和非公平锁
公平锁：先来先得，按照请求时间顺序获取锁
非公平锁：先来后到，根据锁状态判断是否获取锁，效率高

公平锁会降低吞吐量，通常仅在需要避免饥饿时才使用
```java
ReentrantLock lock = new ReentrantLock(true); // 公平锁
ReentrantLock lock = new ReentrantLock(); // 非公平锁，默认
```
获取锁：
```java
lock.lock();
```
## tryLock() 常识获取锁
tryLock()方法：避免尝试获取锁无限等待，立即返回是否获取成功
```java
boolean isLocked = lock.tryLock();
// 带超时的tryLock()方法
boolean isLocked = lock.tryLock(1, TimeUnit.SECONDS); // 1秒内获取锁
```
如果获取成功，返回true，否则返回false

## 死锁
两个或多个线程互相持有对方需要的锁，导致永远等待。
死锁条件：
1.互斥
2.请求与保持
3.不可剥夺
4.循环等待

避免死锁方法：
1.破坏请求与保持：一次性申请所有资源锁
2.破坏循环等待：统一加锁顺序
3.使用tryLock()超时机制：在获取锁时设置超时时间，避免无限等待


# 线程池与 Executor 框架
## 四种常用线程池
Executors类提供了四种常用线程池
1. newFixedThreadPool(int nThreads)
固定线程数，超出任务数的线程会等待
适用负载较重的任务，任务执行时间长
```java
ExecutorService executor = Executors.newFixedThreadPool(5);
```
2. newCachedThreadPool()
缓存线程池，超出任务数的线程会等待，空闲线程会被回收
适用短生命后期的异步任务，任务执行时间短
```java
ExecutorService executor = Executors.newCachedThreadPool();
```
3. newSingleThreadExecutor()
单线程池，所有任务会按顺序执行
适用需要保证任务按顺序执行的场景，如日志写入
```java
ExecutorService executor = Executors.newSingleThreadExecutor();
```
4. newScheduledThreadPool(int nThreads)
定时线程池
适用定时任务和周期任务。
```java
ExecutorService executor = Executors.newScheduledThreadPool(5);
```
四种实际上都是通过 ThreadPoolExecutor 构造器实现的。

## 工作队列
工作队列：用于存储等待执行的任务队列，超出线程数的任务会进入队列等待执行。
1. ArrayBlockingQueue：固定大小的阻塞队列
2. LinkedBlockingQueue：无界阻塞队列
3. PriorityBlockingQueue：优先级阻塞队列
4. SynchronousQueue：无界阻塞队列，每个任务必须等待另一个线程取走

## 拒绝策略
拒绝策略：当工作队列也满了，如何处理新任务。
1. AbortPolicy：直接抛出异常
2. CallerRunsPolicy：调用者线程运行任务
3. DiscardPolicy：丢弃新任务
4. DiscardOldestPolicy：丢弃最旧的任务，重新尝试添加新任务

## 提交任务
提交任务：将任务提交到线程池，线程池会根据策略分配任务给线程执行。
```java
executor.submit(task);
```
## 关闭线程池
关闭线程池：在所有任务执行完成后，关闭线程池，释放资源。
```java
executor.shutdown(); // 平滑关闭，等待所有任务执行完成
executor.shutdownNow(); // 立即关闭，中断正在执行的任务
```

注意：
1. 一定要关闭线程池，否则会占用资源。
2. 不要用 Executors创建无界队列线程池，任务过多可能导致内存溢出。
3. 合理设置核心线程数和最大线程数
    CPU密集型：核心线程数=CPU核心数+1
    IO密集型：核心线程数=CPU核心数*2或更多
4. 处理拒绝策略：了解不同策略的后果，根据业务需求选择
5. 避免使用 newCachedThreadPool 提交大量任务，可能创建过多线程导致系统资源不足
6. Future.get() 可能永久阻塞，使用带超时版本，防止等待锁死
